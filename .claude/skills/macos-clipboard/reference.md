# macOS clipboard reference

Research snapshot from September 2026 (macOS 27.0 shipping, 27.2 in beta). Re-check the pasteboard privacy section against each new macOS release.

## 1. Pasteboard types

| Content | UTI | Handling |
|---|---|---|
| Plain text | `public.utf8-plain-text` | Present on almost every rich copy. Source for search text, titles and the dedup hash. |
| RTF / RTFD | `public.rtf`, `com.apple.flat-rtfd` | Store bytes. `NSAttributedString(rtf:)` is safe off the main thread. |
| HTML | `public.html` | Store bytes. Never parse with `documentType: .html` during capture: it synchronizes with the main thread and can time out. |
| Images | `public.png`, `public.tiff`, `public.jpeg`, `public.heic` | Prefer PNG > HEIC/JPEG. TIFF is often huge (a 5K screenshot is ~59 MB); convert to PNG off the gateway. Thumbnails via `CGImageSourceCreateThumbnailAtIndex`. When writing back, offer PNG and TIFF. |
| Files | `public.file-url` | One `NSPasteboardItem` per file. Write back with `writeObjects` using one item per URL. Never read file contents during capture. |
| PDF | `com.adobe.pdf` | Store bytes, capped. |
| Color | `com.apple.cocoa.pasteboard.color` | Keyed-archived `NSColor`. Also detect hex/rgb()/hsl() in text. |
| Web URL | `public.url` | Plus the string flavor. Skip Safari's `com.apple.linkpresentation.metadata` and `com.apple.WebKit.custom-pasteboard-data`. |
| Universal Clipboard | marker `com.apple.is-remote-clipboard` | Data arrives lazily from the other device; the first read can take seconds. Capturing it is a user setting. |

Skip entirely: `dyn.*`, `com.apple.pasteboard.promised-file-url` and the other promise types, `com.apple.NSFilePromiseItemMetaData`, `com.microsoft.ole.source.*`, `com.microsoft.ObjectLink`, `com.microsoft.Link-Source`, `org.chromium.*`.

`NSPasteboard.types` is the union across items and may list types an item lacks; iterate `pasteboardItems` for real per-item types. `NSPasteboardItem` getters return `nil` once ownership changes, so compare `changeCount` before and after reading.

## 2. Privacy markers (nspasteboard.org)

| Marker | Meaning | Spindle |
|---|---|---|
| `org.nspasteboard.ConcealedType` | Confidential (passwords) | Never stored |
| `org.nspasteboard.TransientType` | Will be replaced momentarily | Never stored |
| `org.nspasteboard.AutoGeneratedType` | Placed without user intent | Never stored |
| `org.nspasteboard.source` | Bundle id of the writer | Used for attribution |

Legacy markers treated like `ConcealedType`: `com.agilebits.onepassword`, `com.typeit4me.clipping`, `de.petermaurer.TransientPasteboardType`, `Pasteboard generator type`, `net.antelle.keeweb`.

Who sets `ConcealedType`: KeePassXC, 1Password 8 desktop, Bitwarden desktop (with "hide from history"). Who doesn't: the 1Password and Bitwarden browser extensions (web clipboard APIs can't set custom types). Apple Passwords is unverified; copies from its menu-bar extra were captured by Maccy (#1008) because extras never become frontmost.

Default ignored bundle ids: `com.apple.Passwords`, `com.apple.keychainaccess`, `com.1password.1password`, `com.agilebits.onepassword7`, `com.bitwarden.desktop`, `org.keepassxc.keepassxc`.

Attribution fallback (from Clipy): treat a copy as coming from app X if any of its type strings starts with X's bundle id. This catches menu-bar extras.

## 3. Pasteboard privacy API

Announced April 2025 with the macOS 15.4 SDK. Not enforced in 26.x or 27.0. The opt-in preview default `EnablePasteboardPrivacyDeveloperPreview` was removed in 27.2 beta 2 (release note 186955507), which may mean enforcement is coming. There is no Info.plist key, entitlement or MDM payload for it.

```swift
@available(macOS 15.4, *) var accessBehavior: NSPasteboard.AccessBehavior { get }
// .default (never asked), .ask (alert on each programmatic read),
// .alwaysAllow, .alwaysDeny

@available(macOS 15.4, *)
func detectedPatterns(for: Set<PartialKeyPath<NSPasteboard.DetectedValues>>) async throws
    -> Set<PartialKeyPath<NSPasteboard.DetectedValues>>     // no alert
@available(macOS 15.4, *)
func detectedMetadata(for: Set<PartialKeyPath<NSPasteboard.DetectedMetadata>>) async throws
    -> NSPasteboard.DetectedMetadata                         // no alert (e.g. \.contentType)
@available(macOS 15.4, *)
func detectedValues(for: Set<PartialKeyPath<NSPasteboard.DetectedValues>>) async throws
    -> NSPasteboard.DetectedValues                           // ALERTS
```

Swift 6.1 rejects calling these from `@MainActor` ("non-sendable result type ... cannot be sent"). Convert to a Sendable value inside a nonisolated function:

```swift
struct DetectedKinds: OptionSet, Sendable {
    let rawValue: Int
    static let webURL = DetectedKinds(rawValue: 1 << 0)
    static let link = DetectedKinds(rawValue: 1 << 1)
    static let email = DetectedKinds(rawValue: 1 << 2)
}

@available(macOS 15.4, *)
nonisolated func detectKinds(on pasteboard: NSPasteboard) async -> DetectedKinds {
    guard let found = try? await pasteboard.detectedPatterns(
        for: [\.probableWebURL, \.links, \.emailAddresses]) else { return [] }
    var kinds: DetectedKinds = []
    if found.contains(\.probableWebURL) { kinds.insert(.webURL) }
    if found.contains(\.links) { kinds.insert(.link) }
    if found.contains(\.emailAddresses) { kinds.insert(.email) }
    return kinds
}
```

What users see when enforced: an alert "<App> is trying to access the pasteboard" whose Allow is one-time. The app then appears in System Settings → Privacy & Security → Paste from Other Apps with Ask / Allow / Deny.

Deep links:
- Paste from Other Apps: `x-apple.systempreferences:com.apple.settings.PrivacySecurity.extension?Privacy_Pasteboard`
- Accessibility: `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`

Strategy: poll `changeCount` only; on change read `accessBehavior`; `.alwaysAllow`/`.default` capture; `.ask` degraded mode; `.alwaysDeny` banner. Onboarding does one deliberate read so the app shows up in Settings, then deep-links there. Writes need no permission.

Open risk to test on each release: whether the target app's read after our synthetic ⌘V counts as user-initiated. Test with `defaults write com.apple.TextEdit EnablePasteboardPrivacyDeveloperPreview -bool yes` on 15.4–27.1 and on a 27.2+ VM.

## 4. Paste injection

TCC has three separate services (Apple DTS, forum thread 820594): `PostEvent` (posting events), `ListenEvent` (Input Monitoring) and `Accessibility` (AX inspection). PostEvent and Accessibility both show under Privacy & Security → Accessibility. PostEvent works inside the App Sandbox; Accessibility does not. Spindle needs only PostEvent.

Layout-aware key code for "v": look it up with `UCKeyTranslate` in the current layout, then in `TISCopyCurrentASCIICapableKeyboardLayoutInputSource()`, then fall back to `kVK_ANSI_V`. Layouts named "… ⌘" (e.g. "Dvorak – QWERTY ⌘") switch to QWERTY while ⌘ is held, so use the ANSI code for them. TIS calls belong on the main thread.

```swift
let source = CGEventSource(stateID: .combinedSessionState)
source?.setLocalEventsFilterDuringSuppressionState(
    [.permitLocalMouseEvents, .permitSystemDefinedEvents],
    state: .eventSuppressionStateSuppressionInterval)
let flags = CGEventFlags(rawValue: CGEventFlags.maskCommand.rawValue | 0x0000_0008)  // + left ⌘ device bit
let down = CGEvent(keyboardEventSource: source, virtualKey: keyCode, keyDown: true)
let up = CGEvent(keyboardEventSource: source, virtualKey: keyCode, keyDown: false)
down?.flags = flags
up?.flags = flags
down?.post(tap: .cgSessionEventTap)
up?.post(tap: .cgSessionEventTap)
```

Before posting: target frontmost (`target.activate(from: .current, options: [])` then wait up to 500 ms), physical modifiers released (`CGEventSource.flagsState(.hidSystemState)`), 40 ms settle. If `IsSecureEventInputEnabled()`, tell the user instead of silently failing.

"Paste and restore the previous clipboard": the target reads asynchronously; restore after at least 300 ms and mark the temporary write `org.nspasteboard.TransientType`. Skip it when `accessBehavior` is `.ask` or `.alwaysDeny`, since snapshotting is itself a read.

## 5. Carbon hotkey

`RegisterEventHotKey(keyCode, modifiers, EventHotKeyID(signature:id:), GetApplicationEventTarget(), 0, &ref)` plus one `InstallEventHandler` for `kEventClassKeyboard`/`kEventHotKeyPressed`. The handler runs on the main thread; dispatch on `EventHotKeyID.id` read via `GetEventParameter(..., kEventParamDirectObject, ...)`. Keep the owning object alive while registered; the handler context is unretained. macOS 15.0–15.1 rejected ⌥-only and ⌥⇧-only combos (fixed in 15.2).

## 6. Panel recipe

```swift
final class PanelWindow: NSPanel {
    init(contentView: NSView) {
        super.init(
            contentRect: NSRect(x: 0, y: 0, width: 760, height: 460),
            styleMask: [.nonactivatingPanel, .titled, .fullSizeContentView],  // .nonactivatingPanel only works here
            backing: .buffered, defer: true)
        isFloatingPanel = true
        level = .floating
        collectionBehavior = [.moveToActiveSpace, .fullScreenAuxiliary, .transient, .ignoresCycle]
        hidesOnDeactivate = false
        titleVisibility = .hidden
        titlebarAppearsTransparent = true
        isMovableByWindowBackground = true
        backgroundColor = .clear
        isOpaque = false
        isReleasedWhenClosed = false
        self.contentView = contentView
    }
    override var canBecomeKey: Bool { true }
    override var canBecomeMain: Bool { false }
}
```

- Screen: the one containing `NSEvent.mouseLocation`, clamped to `visibleFrame`.
- Vibrancy before macOS 26: `NSVisualEffectView` with `.popover`, `.behindWindow`, `state = .active` (the app is never active, so the default state renders flat).
- Liquid Glass: `glassEffect(_:in:)` / `NSGlassEffectView`, macOS 26+. A non-opaque window's glass didn't refresh its backdrop while inactive until 26.4.
- macOS 26 CoreText hang: two or more U+FFFC plus non-Latin text with single-line middle truncation spins at 100% CPU (Maccy #1520).
- macOS 27 hides menu item images by default for apps linked against the 26+ SDK; set `NSMenuItem.preferredImageVisibility` where icons matter.

## 7. Login item

`SMAppService.mainApp.register()` / `unregister()` / `status` (`.enabled`, `.requiresApproval`, `.notRegistered`, `.notFound`). Register only on user opt-in, re-check status at launch, `SMAppService.openSystemSettingsLoginItems()` for `.requiresApproval`.
