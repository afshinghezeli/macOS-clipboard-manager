# macOS clipboard platform rules

These rules come from other clipboard managers' crash reports and issue trackers. Details, API signatures and sources are in [reference.md](reference.md). Read the matching section there before writing new code in that area.

## Capture

- `PasteboardGateway` (`@MainActor`) is the only code that touches `NSPasteboard.general`, for reads and writes (ADR 0004). NSPasteboard isn't thread-safe and AppKit mutates its state on the main thread, so background access crashes (ClipCascade #173, Clop). The price is that reads are synchronous calls into the pasteboard server, so keep them cheap: allow-listed types only, size caps, no file promises, PNG instead of TIFF, and hand bytes to the `Ingestor` actor immediately.
- The monitor polls `changeCount` every 500 ms with 100 ms tolerance on a `.common`-mode timer (keeps firing during menu tracking). It backs off to 2 s after 60 s without user input, pauses on screen sleep or session switch, and polls at once on wake and when the panel opens.
- Wrap each capture in an `OSSignposter` interval. A capture over 16 ms on the main thread is a bug to investigate.
- Check markers from `types` before reading any content: `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`, plus the legacy ones in reference.md. A marked copy is never stored.
- Read an allow-list of types per `NSPasteboardItem` (text, RTF, RTFD, HTML, file URL, URL, PNG, TIFF, JPEG, HEIC, PDF, color) with per-type size caps. Skip `dyn.*`, file promises, Office/OLE and Chromium internals. Never call `NSImage(pasteboard:)`.
- Re-read `changeCount` after reading; if it moved, the items were stale. Record our own writes' change counts and ignore them.
- Source app: `org.nspasteboard.source` if present, else the frontmost app at detection time, plus the type-prefix heuristic for menu-bar extras.
- Never parse HTML with `NSAttributedString` during capture. Store bytes; derive text from the plain-text flavor.

## Pasteboard privacy (macOS 15.4+)

- `accessBehavior == .default` means "never asked", not "allowed". `.ask` means every read pops a system alert: stop background reads and switch to degraded mode (placeholder entries from `detectedPatterns`/`detectedMetadata`, which don't alert). `.alwaysDeny`: don't read, show a banner with the Settings deep link.
- Never retry a failed read in a loop; stamp each change count as handled.
- Calling the async `detected*` APIs from `@MainActor` doesn't compile under Swift 6.1; use the nonisolated wrapper in reference.md.

## Paste

- Post ⌘V with `CGEvent` under the **PostEvent** privilege (`CGPreflightPostEventAccess` / `CGRequestPostEventAccess`). Don't ask for full Accessibility. It works in the App Sandbox.
- Capture the target app when the hotkey fires. The panel is non-activating, so the target normally stays frontmost; if it doesn't, re-activate it and wait until it is.
- Wait until physical modifiers are released (⌘⌥V means "move" in Finder), settle 40 ms, resolve the V key through the keyboard layout (not `kVK_ANSI_V`), add the left-⌘ device bit `0x08`, post to `.cgSessionEventTap`.
- Request PostEvent from an onboarding button, never at launch. Poll `CGPreflightPostEventAccess()` while onboarding is visible; there is no grant callback.

## Hotkey

- Carbon `RegisterEventHotKey`: no permission prompt, sandbox-safe, consumes the event. Default shortcuts include ⌘ or ⌃. Character-producing combos don't fire while Secure Input is on; tell the user.

## Panel

- `NSPanel` with `.nonactivatingPanel` in the **initializer** (adding it later breaks key input), `canBecomeKey = true`, `collectionBehavior = [.moveToActiveSpace, .fullScreenAuxiliary, .transient, .ignoresCycle]`, placed on the screen under the mouse, dismissed on `resignKey` except for our own sheets and Quick Look.
- The agent app still needs a main menu with an Edit menu, otherwise ⌘C/⌘V/⌘A don't work in the search field.
- Use `NSStatusItem`, not `MenuBarExtra`. macOS 26 can hide menu bar items ("Allow in the Menu Bar"), so everything must stay reachable through the hotkey and reopening the app.

## Permissions and signing

- TCC remembers the app's designated requirement. Ad-hoc signed builds change it on every build and silently lose PostEvent. Dev builds are signed with the stable local identity from `make setup-signing` and use the `.dev` bundle id.
- Always launch the bundle with `open`; running the raw binary makes TCC attribute prompts to Terminal.
- Reset while testing: `tccutil reset PostEvent com.afshinghezeli.Spindle.dev`.
